[.description]
--
How the Redis persistence store tracks which keys belong to a workflow instance, so it can remove them on instance completion and reload them when restoring pending instances after a restart.

The choice trades write throughput against removal/restore cost:

 * `indexed` (default) keeps a per-instance Redis Set so removal and restore avoid scanning the keyspace, at the cost of one extra `SADD` on every write. Best for many short-lived instances or frequent removal.
 * `scan` keeps no index and falls back to a keyspace `SCAN` for removal and restore. Best for few, long-lived instances with many tasks, where removal is rare.

Both modes remain interoperable: switching to `indexed` lets existing unindexed instances fall back to a one-time `SCAN`, and instances written while `indexed` are still removable under `scan`.
